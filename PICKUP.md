### Import contract

Named table `Peregrine_Metadata`: columns `key,value`, metadata including schema/template version `1`, workbook/entity IDs, name/type, financial year `2025`, synthetic `true`, baseline version `1`, status `synthetic_reviewed`.

Named table `Peregrine_Lines`: exact columns:

`line_id,entity_id,financial_year,category,label,component,amount,currency,basis,source_ref,recurrence,request_text`

`amount` is an AUD number or blank, never an imported formula. App converts to integer cents. Workbook status text never constitutes authenticated approval.

Stable line IDs:

- Alex: `ALE-EMP`, `ALE-INT`, `ALE-DIV-CASH`, `ALE-DIV-CREDIT`, `ALE-TRUST`.
- Sam: `SAM-EMP`, `SAM-INT`, `SAM-TRUST`.

Evidence CSV contract:

`document_id,line_id,entity_id,financial_year,component,currency,basis,amount,description`

For FY25 individual references: wages item 1, interest item 10, dividends item 11. These are not Xero account codes. Trust-derived components can map to different tax labels; no complete mapping or tax computation is implemented.

### Important limits — describe honestly

The current app is a **browser-local synthetic-data demo**, not the complete production architecture. No live Supabase, Google Drive, Xero, AI extraction, email delivery, scheduler, or ATO lodgment exists. The UI explicitly labels these limits.

Requests currently use deterministic demo rules; no LLM calls. Evidence intake supports structured CSVs, not arbitrary PDF/image OCR. A client-view toggle is a simulation, **not a permission boundary**. Local activity history is not tamper-proof. Production needs authenticated per-entity server-side transitions, private document storage and durable outbox jobs.

Review export edits only `decision` and `review_note`, not arbitrary adviser adjustments or a full current-year compliance workbook. An immutable accepted FY26 snapshot rolling into FY27 has not been implemented. Do not claim the full annual loop is complete.
